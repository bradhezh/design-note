---
title: 1.5. JavaScript — Value-Based Typing
---

Parallel to metaprogramming, dynamic typing can go a step further — types can belong to each individual instance, meaning that data memory layouts and valid operations depend on values. Consequently, no types are needed during design for functions to operate on proper data, as functions operate on any data with proper values. In fact, types become fully dynamic to vary with values at runtime, leaving functions as the effective unit of design. Without types as mechanisms, functions are reusable across values rather than instances, aligning with the traditional data-and-process paradigm. Moreover, value-based typing typically implies full dynamic binding, since operations depend on values and functions are essentially methods operating on objects. This allows frameworks to simply use callbacks for wiring-up.

Interpreted languages such as JavaScript and Python are typically value-based, but they can also support other paradigms. For example, without types, there cannot be multiple instances of the same type. Also note that only global functions (methods of global objects) are reusable at the program level. Classes remain valuable for multiple instances, non-global objects to be reusable. In practice, interpreted languages usually support the class-based paradigm in a runtime way, where classes are essentially functions to create instances. Based on this, decorators can also be functions to be called with the class definition.

Note that in JavaScript, decorators refer to Higher-Order Functions (HOF), which are inherent in functional languages including JavaScript. They take functions as parameters and return new ones with the same interface as the one to be decorated. Class decorators are introduced by TypeScript. However, TypeScript neither touches JavaScript value-based dynamic typing nor imposes any class-based paradigm. Global objects and functions, as well as classes and class decorators, exist as parallel paradigms widely used in JavaScript/TypeScript. For example, React and Express lean to an object-and-function style, whereas Angular and NestJS adopt decorator-based DI. TypeScript did not create a new compiled language, and "transpile" might be less misleading than "compile" in this respect. Python, by contrast, chooses the class-based paradigm as its primary style.
